# Yono Music 1.2.0 — Preview 2

Requested update: always retain the source audio format; recognize shared links more reliably; save covers even when the original container is WebM or Opus. This continues Preview 1 and retains its native UI, compact download flow, selected-source library, owner branding and offline playback.

## Implemented behavior

- Original format is the default and the only accepted acquisition output. The core and API reject conversion requests before downloading. There are no encoder/postprocessor calls in the acquisition path. An MP3 source stays MP3; WebM/Opus stay in their original container/codec. Metadata and supported embedded covers can update container tags without re-encoding audio.
- The link parser recognizes captioned/Markdown URLs, known service URLs without a scheme, YouTube shorts/embed/live/v paths, attribution share wrappers and Spotify locale/embed playlist URLs. Recognizing a `/live/` URL does not permit an ongoing live stream. Invalid credentials, private addresses, malformed IDs and dynamic playlists remain rejected. Signed audio query parameters are preserved. Multiple entries retain individual results.
- Known Spotify short-share hosts have an explicit, bounded HTTPS redirect path to open.spotify.com. Spotify remains metadata-only and requires authorized API access; there is no configured OAuth/token screen. Short-link routing has fixture coverage only, not a live Spotify claim.
- Public WebM/WEBA audio links and provisionally identified extensionless standalone audio keep the explicit source. They do not silently search for a different recording. Native validation still rejects video tracks, incomplete or corrupt audio before publishing.
- Covers are fetched independently of the audio extension. Where supported (including Ogg Opus), Mutagen embeds the cover. A companion `Artist - Title.cover.jpg/png` is saved through the same non-overwriting, checksummed SAF mechanism in the playlist folder. WebM uses this companion instead of an audio remux/conversion. Room stores the exact content URI; the app artwork component and MediaSession use that URI. Explicit rescans preserve its binding and the verified title/artist/album even when WebM has no readable embedded tags.
- `Ambil sampul` in the existing result dialog fetches a missing companion cover for a previous plan. It never fetches, copies or modifies the existing audio. Receipts prevent repeated companion copies. This uses persisted plan metadata; it is not a global artwork scan.
- Cover availability is honest: unavailable JPEG/PNG artwork is reported in details. Sources without an accessible cover cannot be guaranteed a real cover; none is invented. Current retrieval supports the reviewed catalogue image hosts, Wikimedia and the same HTTPS origin for explicitly selected direct audio. Arbitrary third-party CDN images and WebP-only sources may not provide a usable cover.
- No new main navigation destination or long download-page sections were added. Cover state/actions are inside the existing lazy detail dialog.
