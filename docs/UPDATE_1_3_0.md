# Yono Music 1.3.0 — collection repair

Yono Music, open source oleh **Karisyono**. This release continues commit 528fa935 (1.2.0 Preview 3), preserves the owner-selected mist-blue YONO identity and Home / Library / Search / Playlists. Version code **6**, version name **1.3.0** (`1.3.0-dev` on Dev). The official stable GitHub release is 1.3.0; earlier tags and releases are retained.

## Collection safety and moved files

Room migration **2→3** adds verified byte hashes, source identity/URL, metadata provenance, artwork revision, typed location states and qualified listening events. Migration **1→2→3** remains available; there is no destructive migration. Aliased index rows are retained inactive instead of automatically deleted. Favorite, playlist/order, history, download and listening references are rebound transactionally when an identity is explicitly reconciled.

An explicit rescan enumerates only enabled selected SAF sources. New/changed audio is hashed off the UI thread. Same-URI cached hashes require matching positive size and modification time. A unique SHA-256 match reconnects a moved/renamed recording to its existing internal ID. Filename, artist/title similarity, duration alone and a shared source ID never prove that two recordings are identical. Several candidate old identities produce a manual relocation choice. Exact duplicate bytes can have several selected locations. Different bytes with the same filename remain separate recordings.

Enumeration is staged before each source transaction. A failed provider retains membership and collection context. States distinguish **available**, **old location missing**, **folder permission lost**, **storage temporarily unavailable**, **audio unreadable**, and **ambiguous location**. The shared MediaSession observes committed track changes and rebinds queued URIs while retaining playback position and paused/playing intent. No user audio is automatically deleted, renamed or moved. Selecting a destination whose name already equals the playlist folder does not add the same folder again.

A file outside selected SAF coverage requires **Pilih lokasi baru** / **Hubungkan ulang folder**. Older installations may have no historical hash for a file moved before this update; its identity cannot be retroactively proven. Explicit relink then requires the user's choice and checks duration. Only a new valid grant makes that location accessible. Files re-tagged by another application have different whole-file hashes and are not automatically treated as unchanged recordings. A provider silently changing bytes while preserving size and timestamp requires reimport/manual verification; the cache cannot infer hidden changes.

## Original audio, metadata and artwork

The engine keeps the downloaded original audio container and encoding; no MP3 conversion or bitrate inflation. Supported safe tagging uses the existing Mutagen implementation; WebM/WAV retain their metadata in Room plus a portable companion. Source/user/manifest fields take precedence over a filename guess, with actual tags used for missing fields. All known artist credits are retained. Unknown album/artist remain unknown, and an uploader/channel is not assumed to be an artist.

New downloads publish a **`yono.music.metadata` schema-1 JSON** beside the audio, containing the exact published audio SHA-256, size, duration, title, artist array, known album, source identity, canonical source URL, and relative cover filename/hash. No internal track ID or Android content URI grants are portable. Signed URL query credentials are omitted. Sidecars use safe basenames, bounded JSON/fields and a hash match before applying metadata; they cannot overwrite unrelated audio or follow arbitrary file paths. Keep the audio, JSON and referenced cover together when copying a collection. Folder import can rediscover them after renaming or moving. Equal-revision conflicting metadata is not silently selected.

**Edit metadata** corrects title/artists/album and selects a local cover without fetching audio. It saves Room fields and a new companion where the chosen folder is writable. **Repair artwork** uses a known app download plan and verifies the current audio hash before fetching just its available cover; no audio redownload. If no known source exists, select a local picture. Explicit JSON import/export is available for a single audio document. A single-file permission cannot implicitly read sibling JSON/images; select the folder or import metadata/cover explicitly. Exporting JSON alone does not copy a separate picture: copy that referenced image too. Existing user edits are retained on later scans.

Artwork decode buckets follow requested display pixels/density (128–1536 px), with distinct thumbnail/large requests, bounded memory/decoding concurrency and audio/art revision cache keys. Negative lookups expire after two seconds; a repair revision triggers another load. Shared cover hashes are cached once during a scan. Small source artwork remains small; no artificial HD label or upscaling is introduced. Network cover acquisition accepts JPEG/PNG up to 4 MiB; local image selection allows up to 8 MiB. Android codec/tag/embedded-cover support still depends on the container and platform. Notification/lock-screen artwork invalidation for an externally overwritten same-URI image was not independently tested.

## One persistent download list

**Import → Downloads → Daftar** and the active top-bar indicator open the same history/list. Each item shows known title/artists/cover, waiting/metadata/downloading/metadata-and-cover-processing/done/failed/cancelled status, genuine byte progress or an indeterminate indicator, completed count and actionable failure text. Cancel one acquiring item or the whole operation, retry failed/cancelled items, open readable output and select earlier plans. No pause/resume UI is offered.

Playlist creation and its durable plan→playlist mapping are committed in one Room transaction. The existing WorkManager request, atomic plan JSON, SQLite identity index and SAF publication receipts provide recovery. A result is terminal only after publication and native readability/metadata validation; manifest-publication failure retains the receipt for retry without another audio transfer. Retrying a missing early item inserts it before the next downloaded sibling while retaining existing manual playlist edits. Downloads never search unselected storage for duplicates. Local selected-source byte identity and app-owned history remain the allowed scopes.

Library enumeration is bounded to 10,000 audio files, 20,000 directories, 10,000 small manifest candidates and 2,000 image candidates per selected source; split very large trees into narrower sources.

Limits: one operation at a time; deadlines are 15 minutes for metadata/control and two hours for acquisition, with network read timeouts. A blocking provider/network call can delay cancellation until it returns. The current history selector loads the newest 100 plans under a 24 MiB budget; older private journals remain on disk. No background auto-download is initiated by paste or startup. Full OS process-death recovery and real removable-media disconnection need further device testing; recreation of clients and publication-receipt recovery are separately tested fixtures.

## Home, Smart Mix and motion

Home uses a small greeting, up to two recent tracks, six recent additions and only known album highlights. Continue listening and large repeated navigation shortcuts are removed. Empty sections disappear, and Home's list state is retained when switching destinations. Bottom navigation and the mini-player occupy reserved scaffold space.

Smart Mix is optional, offline, and changes no audio, album tags or custom playlists. A qualified event requires **30 seconds or half the recording**, with a minimum of five seconds capped by actual duration; paused/buffering time and seek jumps do not count. Events start with this version; old last-played timestamps are not fabricated into play counts. Qualified listening events currently remain in the local Room database; the collection JSON backup retains its existing favorite/playlist/last-history fields but does not yet export these new event counts. No mix appears until at least five qualified events across three tracks, and each displayed mix needs three tracks. Rules are visible: repeated plays (at least two/song), low-play favorites (at most one), rediscovery (added >30 days, last qualified play >14 days), and primary credited artists with at least three plays. No mood/genre inference or tracking. Disable in Settings.

Page fades, player entry, action/favorite state and download status transitions are short and stop under app reduced motion or disabled Android animators. The player uses the existing shared session; this is not a separate second player or a claimed shared-artwork morph.
