# Security and privacy — Yono Music

Maintainer/creator: Karisyono. Report reproducible non-secret issues through https://github.com/arisynn/yonz-music/issues. Never paste tokens, keys, cookies, private music lists or sensitive exploit data into a public issue.

The app has no advertising, analytics, account, tracking SDK or custom server. Local listening and stored collections work offline. Optional downloads and production GitHub version checks require INTERNET. Explicit source operations may contact the requested source/CDN; Commons catalog requests contact Wikimedia; update checks contact GitHub. A request necessarily exposes the device's normal network address and requested URL to that service. No private library is uploaded for matching.

Library access uses user-chosen SAF documents/trees. No READ_MEDIA_AUDIO, READ_EXTERNAL_STORAGE, MANAGE_EXTERNAL_STORAGE, microphone, contacts, SMS, location, accessibility, overlay or root permissions are requested. Removing a source changes its active index and preserves original music/collections. Existing music is never overwritten or deleted. Download outputs and metadata sidecars are created only in the chosen destination.

Foreground playback and user-started durable downloads use the appropriate Android foreground-service types. WorkManager adds boot/network/wake capabilities for work recovery. Notifications are optional under Android's runtime policy. REQUEST_INSTALL_PACKAGES opens Android's official user-confirmed updater flow; no silent installation, automatic uninstall or Play Protect bypass is implemented.

The engine is bundled/pinned at build time. Source URLs are bounded HTTPS without embedded credentials/private addresses; redirects are checked, certificates verified, media/JSON/artwork bounded, retries/concurrency controlled, temporary output private, and final audio checked natively before publication. The fixed QuickJS runner has no file/network/process JS APIs and memory/time/output limits. No shell command supplied by a user, cookie/login import, DRM bypass, runtime pip/npm/plugin download or downloaded executable is supported. Some extractors require facilities intentionally not provided and may fail with explicit errors.

Updater metadata pins package/version/channel/SDK/ABI/named artifact/hash/certificate. Actual APK signatures are cryptographically checked before a standard PackageInstaller session. Private/nonexported callbacks are nonce/session checked. Replacement cleanup rechecks installed package/code/certificate and deletes only validated owned cache filenames. It never treats returning from installer as success.

Release key persistence, old-test signing incompatibility and recovery limitations are in [SIGNING_AND_RECOVERY.md](docs/SIGNING_AND_RECOVERY.md). Private keys/passwords remain outside the repo and are excluded from public artifacts. The exact resolved Maven/PyPI inventory was queried against OSV; no advisory matches were returned. This is not a comprehensive native CVE audit or an external APK security certification. Actual OS installer checks are documented in TEST_REPORT.md. No external security-scanner, Play Protect approval or Play Store acceptance is claimed.

The 1.3 collection repair preview adds bounded, hash-bound portable JSON. An imported manifest cannot grant URI access or choose internal track IDs; cover references are basenames validated against actual image bytes within selected scope. Existing audio is never overwritten for metadata repair. Per-source scan mutations and collection identity rebindings use Room transactions; unmatched/ambiguous rows remain recoverable. Smart Mix records qualified local listening in Room only, can be disabled, and sends no listening data off-device. Test-only fixture providers and local HTTP setup are absent from production. No newly introduced dependency version is claimed to have an independent scanner certification.

## 1.4.0 optional connections and companions

Spotify uses browser OAuth PKCE S256, random state with a ten-minute expiry and single-use callback, exact package-specific redirect validation, fixed HTTPS token endpoint, no client secret, and AES-GCM tokens in no-backup storage backed by Android Keystore. Config/tokens never enter plans or Room. Disconnect deletes local tokens. Live OAuth has not been exercised with a configured Developer app in this environment.

Companion artwork paths accept only a sibling filename or `.cover/<filename>`; traversal and arbitrary URIs remain rejected. Hash verification binds artwork and audio. `.nomedia` is created only inside the companion directory, never the audio destination. Existing audio/covers are never overwritten or moved.
