# Yono Music 1.5.0-preview.4 — actual verification

Preview assembly/lint passed; 0 lint errors, 116 warnings. **133 JVM tests, 177 host Python tests and 19 distinct Android fixture/regression cases passed.** The final artifact's two streaming/queue/UI cases were then repeated at font100% and150%, both passing. Repeats are not counted as additional distinct cases. Raw evidence is in docs/verification/v1.5.0-preview.4. Physical-device, HyperOS, external security scanner and Play Protect success are not claimed.

## Android: real runtime, controlled transport

The complete19-case API29 software-emulator suite passed in303.338s. Six StreamTransportTest cases exercise401/403 refresh with a pinned format, exact byte ranges, rejection of changed format/length, bounded ignored-range fallback, truncation/timeout/cancellation, persistent per-DataSource retry budget and429/no refresh. StreamFormatsTest uses owned MP3, WebM, Opus and M4A assets through the actual Media3 service/DataSource, asserting decode with advancing position and seek. A generated20s WAV injects a real SocketTimeoutException after32768bytes; Media3 reopens a nonzero byte range and resumes, then keeps advancing while the Activity is backgrounded. This transport uses constructor-injected fake HTTPS responses; it makes no internet request. See stream-format-qa.json. It does not prove live CDN or all device codec behavior.

Two SelectedQueueRecoveryTest cases use real Room/AppState, WorkManager and an owned persisted SAF fixture. Repeated retry schedules once, superseded work IDs cannot overwrite/re-execute a newer generation, completed rows cannot be cancelled, finished work reconciles an exact-source contentURI/SHA256 receipt without redownloading or changing collection rows, and wrong hashes fail. Actual already-cancelled worker nodes succeed without cancelling dependents. These are controlled publication/recovery fixtures, not live queued downloads or a force-kill-at-every-step campaign.

The other10 cases cover the same native streaming session's decode/range/seek/mixed queue/next/background/pause and UI, persisted selected queue dedup/cancel/recovery, actual Python search bridge/cancellation, private optional history cleanup, native shuffle order, queue move/swipe/Undo/duplicate occurrences, local playback/audio focus/sleep timer, two updater NaN regressions and bundled Chaquopy doctor/QuickJS/110-entry local prepare/snapshot. Collection fixtures are restored. No uninstall, clear-data, whole-storage scan or user file move/delete is used.

## Failures found and corrected

The first nine-case native run passed6 and failed3. Two refresh tests had a fake HttpURLConnection header implementation reading its inherited responseCode field (-1), rather than overridden getResponseCode(); the fixture was corrected. The multi-format case decoded MP3 but then read MediaController.duration off its application thread; duration/position assertions were moved to the main-thread test helper. After these fixes all19 cases passed. Initial logs remain native-initial-fixture-failures.log; they are not presented as a clean initial pass. After shortening the horizontal labels, one coordinate-driven UI run failed to open approval. A subsequent accessibility-action attempt found that the description node was nonclickable. The tile was replaced with the standard Material3 tonal button; the harness resolves its clickable ancestor and uses actual injected touch. Both failed logs remain ui-initial-compact-click-failure.log and ui-initial-accessibility-node-failure.log. This is emulator touch injection, not physical-device testing.

During receipt/metadata retry work, a broad text edit accidentally altered an unrelated Python choose block, causing IndentationError and a61-case discovery with7 errors. The original choose behavior was restored before the final177-case host pass. host-initial-import-failure.log retains that failure. Final host tests include pinned-format/error redaction, same-source retry and verified duplicate receipt cases, plus original-format/tag/art/portable identity/recovery fixtures. Host FFmpeg generates and inspects owned fixture audio only; it is not embedded in the APK. JVM cases include strict ranges/expiry TTL, bounded typed retry and receipt/error boundaries alongside existing import/playlist/search rules.
