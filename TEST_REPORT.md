That was a real implementation defect, fixed by retaining the exact ID at transfer too; the existing Media.transfer still rechecks exact ID/access/DRM before fetching bytes. The initial failure log is retained as host-selected-flow-initial.log. The corrected full173-case suite passed.

That new full-flow fixture uses an owned generated sine recording encoded to WebM on the host, a scoped source-metadata fixture, actual Engine prepare/acquire, actual Media validation/finish and host DirectoryStore. It asserts no catalogue substitution, unchanged WebM SHA256, audio directly in the destination with playlist disabled, saved .cover/.nomedia and source identity reuse without a second transfer. The transfer itself is a local fixture copy. This is not a live platform download, Android SAF publication or proof of all network extractors. Existing real-tone MP3/M4A/Opus/WebM metadata/cover/packet-preservation fixtures and all import/recovery/network tests passed. Host FFmpeg generates/inspects test media and is not embedded in the APK.

JVM cases cover strict stream source/CDN policies plus authoritative shuffle insertion order and existing collection/import/playlist/search/progress rules. A new queued source cannot substitute a same-title different video based solely on title/artist/duration. Actual safe source/history/hash reuse remains possible.
